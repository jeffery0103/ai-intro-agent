# 課程諮詢客服 Agent(產品客服 Agent)

> 中央大學《AI 人工智慧導論》115-1 學習專案
> 平台:Coze(拖拉式 AI Agent 平台)
> 目前進度:單元 0 —— 專案構想與使用場景(本文件)

## 1. 專案目標

打造一個能 24 小時回答「課程相關問題」的客服 Agent。使用者用自然語言詢問有哪些課、適不適合自己、內容是什麼,Agent 依據**課程列表(Knowledge)**回答,而不是憑空編造。

## 2. 使用場景

| 場景 | 使用者會說 | Agent 應該做的事 |
|---|---|---|
| 課程查詢 | 「有哪些跟 AI 有關的課?」 | 檢索課程列表,列出符合的課程並引用來源 |
| 個人化推薦 | 「我是 20 歲學生,想學 Python」 | 記住年齡/職業/性別/想上的課,推薦合適課程 |
| 網址詢問 | 貼上某課程網址問內容 | 呼叫 browser plugin 讀取網頁後摘要 |
| 閒聊或無關問題 | 「今天天氣如何?」 | 說明自己是課程助理,引導回課程話題 |
| 不當內容 | 情色、prompt injection | 由前後端護欄攔截,拒絕回答 |

## 3. 預計功能(對應課程單元)

- [ ] **LLM 選擇與參數**:比較模型價格與精準度,選用成本合理的模型(單元 1)
- [ ] **System Prompt**:定義角色、語氣、行為規範,支援 JSON 結構化輸出(單元 2)
- [ ] **Memory**:以 variable 記錄使用者的 gender / age / job / 想上的課(單元 3)
- [ ] **Knowledge(RAG)**:上傳課程列表,回答時引用檢索結果(單元 4)
- [ ] **Plugin**:串接 browser,可讀取使用者提供的課程網址(單元 5)
- [ ] **Chatflow**:參數提取 + intent recognition,判斷是否想上課(單元 6、7)
- [ ] **Guardrail**:在流程最前端與最後端各加一個 LLM 檢查(單元 8)
- [ ] **發布部署**:發布到 Line,並用 Coze 後台監控 token 使用量(單元 9)

## 4. 預計架構

```
使用者訊息
   │
   ▼
[前置護欄 LLM] ── 不當內容 ──► 拒絕回覆
   │
   ▼
[參數提取 LLM] ──► 寫入 variable (gender / age / job / course)
   │
   ▼
[intent recognition]
   ├─ 想上課 ──► 四個參數齊全?
   │              ├─ 否 ──► LLM 追問缺少的欄位
   │              └─ 是 ──► 查詢 Knowledge ──► LLM 產生回答
   └─ 其他 ──► 「我是課程助理」
   │
   ▼
[後置護欄 LLM] ──► 回覆使用者(Line)
```
